# i18n runtime (deferred — readiness handled now, machinery later)

- Provenance: task-0006
- Links back to: [`../../adr/0004-i18n-readiness.md`](../../adr/0004-i18n-readiness.md)
- Status: deferred
- Owner: unassigned
- Priority: deferred (no non-English readers today; scalability nice-to-have)

## Problem

The site may eventually need multiple languages. Building a full i18n runtime now would be speculative
infrastructure for zero non-English readers. But retrofitting i18n onto a codebase full of hardcoded strings
is painful, so the cheap prerequisite (string externalisation) is being done now as hygiene; the runtime is
parked here until a real second locale exists.

## Done when

(When picked up) locale-prefixed routing, a message-catalog format with interpolation/pluralisation, a
locale switcher, per-locale `<html lang>` + Open Graph/canonical tags, and a fallback chain are in place,
with the React islands receiving translated strings. Not before there is a genuine second-language need.

## Notes

- **Readiness (done as part of the current pass, not here):** the expanded M6 sweep in
  [`../open/task-0001-pristine-baseline.md`](../open/task-0001-pristine-baseline.md) externalises ALL
  user-facing copy into `src/content/`, so no string is hardcoded. That is the prerequisite; this task is
  only the runtime on top of it.
- **Runtime scope when picked up:**
  - Decide Astro's built-in i18n routing (available since Astro 3.5) vs a library.
  - Reshape `src/content/*.ts` into a locale-keyed structure (deliberately NOT done now — the shape is
    better understood once a real second locale exists).
  - Thread translated strings into React islands (props or a client i18n lib) — coordinate with M5
    (one content-injection convention).
  - Per-locale metadata: `<html lang>`, Open Graph `locale`, `hreflang`/canonical (pairs with Phase 5 A8).
- **Do not** start this until there is a real reader base for a second language, a partner requirement, or
  an explicit org decision. Revisit ADR-0004 at that point.
